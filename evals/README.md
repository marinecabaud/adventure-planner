# Intent evaluation protocol
- `intent-v1.json`: initial reported failure and three counterexamples.
- `intent-v2.json`: 20 test cases with a fixed reference date; 10 Intent Understanding and 10 Context & Assumptions.
- `run-intent.mjs`: executes the current harness and live model, using controlled unavailable weather/routing tools (do not interpret them as real evidence). A structured LLM judge grades observable behavior per expected criterion; separate deterministic checks compare available date/transfer tool arguments. V2 scores the normalized intent fields deterministically, and retains behavioral grading separately. V1 behavior is recorded in baseline-v1.md.
- `run-intent.test.mjs`: mock-only tests for runner and scoring. Run `node --test evals/*.test.mjs`.
- GitHub Actions: choose **Adventure Planner intent baseline → Run workflow**. Uses the existing `ADVENTURE_PLANNER` GitHub secret as `OPENAI_API_KEY`. A change to the workflow triggers a run on main; other runs can be launched manually. Limit 1–20 cases; sequential runs; max 1 intent extraction + 7 agent decisions + one judge per case. OpenAI API costs apply. The workflow has a 25-minute cap.
- Results: GitHub Actions job summary and downloadable JSON artifact with per-case outputs, judgments, deterministic checks, duration and token counts. Compare judged pass rate *and* coverage; never count missing checks as passes. The LLM judge is provisional and needs human calibration. No full agent traces or prompts are transmitted to Langfuse by this CLI runner.
- Run locally only with a securely configured API key: `node --env-file-if-exists=.env evals/run-intent.mjs`. The results directory is generated; don't commit secrets.
- V2 injects the fixed reference clock into the harness and uses a stricter behavioral judge. Raw behavioral scores are not directly comparable to V1. The production site bundle is separate; validate V2 before rebuilding/deploying it.
